# P1.2 — Independent Contractor Case Intake v0.1

**Status:** ACTIVE  
**Purpose:** Acquire independent contractor evidence without leading participants into the frozen P1.1 ontology.

## 1. Minimum case eligibility

A case may count toward the independent-workflow gate only when:
- it represents a contractor organization/process independent of the founder's own Perflex/City Cool operating experience;
- the workflow description comes from a participant with direct operating knowledge and/or original contractor artifacts;
- raw terminology is preserved;
- material uncertainties are marked rather than filled from the project architecture;
- the case is reconstructable step-by-step with roles and artifacts.

A supplier quotation alone is not a contractor workflow case.
A public software case study is not primary contractor workflow evidence.

## 2. Sampling priority

Acquire 3–5 independent cases with deliberate structural variation.

Priority set:
1. UAE main contractor — mixed material + subcontract procurement.
2. UAE/GCC specialist contractor — MEP / fit-out / interiors / other procurement-heavy trade.
3. Contractor with materially stronger ERP/job-cost integration than CAL-001.
4. Case outside the founder's familiar villa/building procurement pattern.
5. Optional additional case with high subcontract/commercial-administration depth.

Do not select cases only because they resemble the current graph.

## 3. Evidence request — minimal useful artifact pack

Ask for redacted examples where confidentiality requires it.

Highest-value artifacts:
- procurement tracker / procurement schedule;
- MR / purchase requisition / package request;
- one RFQ/tender pack;
- two or more supplier/subcontractor quotations or revisions for the same event;
- **actual contractor bid comparison / levelling sheet**;
- DOA / approval matrix or approval evidence;
- resulting PO or subcontract;
- one change/variation or PO amendment;
- one GRN/receipt for goods or one progress claim/certificate for subcontract work;
- retention / advance / recoupment evidence where applicable.

Not every case needs every artifact. Missing artifacts must be explicit.

## 4. Interview rule

Start with:

> Walk through the last real procurement from the moment the need became actionable until the supplier/subcontractor was paid or the commitment was closed. Use the names your team actually uses for every document and status.

Do **not** begin by asking whether they use our objects such as package, commercial event, award proposal, canonical bid line or commitment layer.

## 5. Core reconstruction prompts

Ask in operating sequence:

### Demand / planning
- What makes procurement start?
- What document or message is created first?
- Who creates it?
- Is budget/cost code already known at that point?
- Can procurement start without an approved budget/code?

### Sourcing
- How are bidders selected?
- How is an RFQ/tender issued?
- How do suppliers respond?
- How are revisions distinguished?
- What happens when a supplier declines or simply does not respond?

### Comparison / award
- Show the actual comparison used for a recent award.
- Which fields are manually normalized?
- Where are qualifications/exclusions/alternatives recorded?
- Who can alter the comparison?
- What is the approval/DOA route?
- How is a non-lowest award justified?

### Commitment
- What exactly turns an award into a PO/subcontract?
- Which system/document becomes authoritative?
- Can the issued commitment differ from the approved comparison/award?
- How is that difference controlled?

### Change / current commercial position
- How are variations/PO amendments initiated and approved?
- Where is original value vs approved changes vs current value visible?
- Is there a parallel commitment/cost spreadsheet?
- Which value would management trust during a dispute?

### Receipt / valuation / payment
For goods:
- how are partial deliveries, rejected qty and GRNs handled?
- how does invoice matching work?

For subcontracts:
- how is progress measured?
- who certifies it?
- how is retention calculated and released?
- how are advances and recoupment tracked?

### Technical / external dependencies
- Can material/submittal approval block tender, award, PO release, manufacturing or payment?
- Where is that approval recorded?
- Are programme dates imported, copied or manually tracked?

### Closeout
- What closes the PO/subcontract operationally and commercially?
- What unresolved items survive after completion?

## 6. Truth-location test

For every important status/value ask:

> If two records disagree, which one wins and why?

Record:
- participant-stated authoritative source;
- secondary copies;
- update lag;
- reconciliation method;
- who can correct it;
- whether historical value can be overwritten.

## 7. Unmatched-observation prompt

End every case with:

> What important procurement/commercial step, document, exception or workaround did I fail to ask about?

Then compare the raw workflow to the P1.1 graph only after capture is complete.

## 8. Case acceptance checklist

A case counts as an independent workflow only when:
- independence is explicit;
- workflow is reconstructed rather than summarized;
- roles/artifacts are named or explicitly missing;
- at least one truth-location conflict or explicit no-conflict finding is attempted;
- supplier participation is covered;
- unmatched observation question is answered;
- source/evidence references exist;
- raw terminology remains separable from project normalization.

## 9. Special requirement — real bid leveling

At least one case must provide an original contractor comparison/levelling artifact.

The artifact must be decomposed into:
- source bidder/revision;
- line/item basis;
- unit/quantity normalization;
- qualifications/exclusions;
- adjustments/allowances;
- technical acceptance inputs;
- revised/negotiated offers;
- selected offer;
- approval/award justification.

Assistant-generated comparisons are analysis aids only and cannot satisfy this requirement.
