# 2. Objective

Freeze measurable operating constraints and only the AI-readiness structures that remain safely additive.

The phase must define:

- measurable performance, scale, availability, reliability and recovery requirements;
- security/privacy/residency/retention/observability/export operating contracts;
- attachment/import/rate/concurrency limits and graceful degradation;
- deployment/capability/conformance and operational evidence expectations;
- AI proposal, confidence/uncertainty, abstention, review, evaluation and correction semantics;
- a bounded agent-authority ladder derived entirely from registered deterministic operations;
- tenant isolation across prompts, retrieval, embeddings, memory, evaluation and model-provider paths;
- model/provider replacement, degradation and AI-off operation;
- explicit falsification and pilot-validation debt.

P1.10 decides requirements and semantic controls, not cloud vendor, model vendor, framework, database, queue, observability product, physical topology or code.

---

# 3. Governing thesis

> **Nonfunctional requirements are testable product contracts, and AI is an optional, replaceable proposal-and-orchestration layer over the frozen deterministic system—not a new truth, authority or dependency.**

Every NFR must have a measurable test, declared scope and failure/degradation behavior.

Every AI capability must be removable without breaking deterministic A0–A3 or corrupting history.

# 5. Primary workstreams

## P1.10a — workload and scale model

Define bounded workload classes and measurable assumptions for tenants, users, projects, suppliers, requirements, lines, bids, evidence, events, reports, integrations, concurrent operations and retention duration.

No infinite-scale claim.

## P1.10b — performance and responsiveness

Define percentile targets by operation class and interaction stage, including conventional UI, query, proposal preview, command acceptance, async progress, report execution, export, file processing, search and external task access.

Separate acknowledgement latency from effect completion.

## P1.10c — availability, continuity, backup and disaster recovery

Define service tiers, availability measurement, planned-exclusion rules, RTO, RPO, backup verification, restore testing, regional failure behavior, tenant/export recovery and evidence integrity.

No zero-loss/zero-downtime claim without proof.

## P1.10d — reliability, concurrency, queues and degradation

Define SLO/error-budget semantics, retry budgets, queue age, dead-letter/reconciliation, idempotency retention, continuation-anchor durability, partial/indeterminate visibility, bulk limits, circuit breaking, dependency degradation and manual fallback.

## P1.10e — observability and operational evidence

Define logs/metrics/traces/audit distinctions, correlation identities, health/conformance signals, privacy-safe telemetry, alert ownership, operational evidence retention, customer-visible status and incident timeline obligations.

Observability never becomes business authority.

## P1.10f — security, privacy, residency and lifecycle residual

Define authentication assurance, session/re-authentication, least privilege, secrets/keys, encryption, tenant isolation, secure software/dependency/update expectations, vulnerability handling, audit access, deletion/redaction/legal hold, export/portability, subprocessor/model-provider boundaries and region migration.

Do not invent jurisdiction-specific legal claims.

## P1.10g — data, attachment, import/export and rate constraints

Define file/attachment classes, size/count limits, malware/untrusted-content handling, archive/decompression limits, parsing isolation, quotas, API/channel rate limits, backpressure, export completeness/integrity and bulk/import thresholds.

## P1.10h — capability, deployment and conformance

Define capability flags, deployment profiles, conformance evidence, version compatibility, rollout/rollback, feature disablement, migration compatibility and minimum mandatory deterministic substrate.

No configuration/platform second XL.

## P1.10i — AI object and output grammar

Define AI request/run/proposal/output/evidence/citation identities, task/capability version, model/provider/version, prompt/instruction/config versions, input scope, source cut, retrieval context, confidence/uncertainty/abstention, limitations, safety checks, human review and accepted/rejected/corrected outcome.

AI output is never authoritative fact by itself.

## P1.10j — agent authority ladder

Define closed levels from no action through read/query, draft/proposal, bounded recommendation, human-confirmed command request and narrowly eligible deterministic bounded automation.

No raw DB/event-store write, no self-created operation, no authority inheritance from language, no silent escalation and no general autonomous commercial control.

## P1.10k — AI evaluation, correction and monitoring

Define capability-specific evaluation sets, offline/online/shadow testing, error taxonomy, human correction capture, false-positive/false-negative treatment, calibration/abstention, regression gates, drift/conformance, incident/rollback and learning-data restrictions.

Evaluation results do not become business truth.

## P1.10l — AI isolation, memory, retrieval and provider replacement

Define tenant/project/authority-scoped retrieval, embedding/index/memory isolation, source and time binding, memory lifecycle, prompt-injection/untrusted-content handling, provider data-use controls, model/provider portability, AI-off fallback and no cross-tenant learned influence.

## P1.10m — validation and falsification plan

Carry the unfired contractor/supplier falsification targets into explicit pilot/build gates with kill/revise criteria. Architecture completion must not be misreported as market validation.

# 8. Closure gates

P1.10 may close only if:

G1 — every NFR has a measurable target/test, exact scope, measurement window and failure/degradation behavior.

G2 — workload/scale assumptions are finite, versioned and linked to capacity tests rather than marketing claims.

G3 — acknowledgement, completion, availability, durability, RTO/RPO and recovery meanings remain distinct.

G4 — dependency degradation preserves authority, evidence, idempotency, continuation and effect uncertainty.

G5 — observability provides operational reconstruction without becoming domain truth or leaking tenant data.

G6 — security/privacy/residency/lifecycle controls preserve all frozen authority/evidence/history semantics.

G7 — attachment/import/export/quota/rate controls prevent resource exhaustion, parser abuse and silent truncation.

G8 — capability/deployment/conformance changes are versioned, reversible and cannot silently change historical meaning.

G9 — AI run/output/proposal identity, provenance, source cut, model/config version, uncertainty and review are explicit.

G10 — AI cannot create authority, semantic fields, metrics, commands or facts outside registered deterministic contracts.

G11 — agent authority levels are closed, capability-specific, revocable and safe under partial/indeterminate effect.

G12 — evaluation, correction, abstention and regression gates are capability-specific and do not rely on one generic confidence score.

G13 — prompts, retrieval, embeddings, memory, evaluation data and provider paths remain tenant/context isolated; cross-tenant business influence stays OUT.

G14 — model/provider failure, withdrawal or disablement leaves conventional deterministic A0–A3 and manual/file paths complete.

G15 — validation/falsification debt is explicit with pilot/build gates; architecture completion is not labelled product-market validation.

G16 — no NFR platform, SIEM/GRC, data lake, low-code, model platform or agent second XL; product code remains locked.

G17 — internal hostile audit PASS and Claude hostile audit PASS.

# 9. Hostile scenarios

Attack at minimum:

- vague “fast/highly available/secure/scalable” requirement;
- average latency hiding tail failure;
- accepted request displayed complete;
- async job lost after restart;
- backup exists but restore untested;
- regional outage with false zero-loss claim;
- dependency outage causes unsafe retry;
- stale connector/AI result appears current;
- queue backlog hides effect-indeterminate work;
- telemetry leaks bid/commercial data;
- logs treated as audit/domain truth;
- deletion erases financial meaning;
- legal hold conflicts with deletion;
- residency exception path through model/telemetry/subprocessor;
- zip bomb/malware/parser exploit;
- export silently truncates;
- tenant exceeds quota during tender close;
- rollout changes semantic behavior without version;
- AI invents source/field/metric;
- AI accepts its own proposal;
- AI uses old report/session memory as authority;
- one confidence score across unrelated tasks;
- low confidence but no abstention;
- agent language interpreted as delegation;
- agent resends indeterminate command;
- agent creates bulk operation without frozen member set;
- cross-tenant retrieval/embedding/memory contamination;
- provider trains on tenant data;
- model/provider disappears;
- AI required for first tender;
- evaluation set leakage/overfitting;
- corrections silently train shared model;
- architecture called validated despite unfired contractor tests;
- NFR/SIEM/data/AI platform second XL.
