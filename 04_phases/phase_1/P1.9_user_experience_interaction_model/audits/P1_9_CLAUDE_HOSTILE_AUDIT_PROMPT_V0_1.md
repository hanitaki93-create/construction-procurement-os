# P1.9 — Claude Hostile Audit Prompt v0.1

Please perform an independent hostile audit of the attached self-contained P1.9 User Experience & Interaction Model packet only.

You do not have repository access, and none is required.

Treat the internal PASS as a claim to attack, not as evidence.

Focus especially on:

1. whether every state-changing affordance maps to one registered operation and cannot hide behind navigation, drag/drop, auto-save, import or chat;
2. whether an `InteractionContinuationAnchor` created before effect-bearing transmission truly closes connection/session loss before any result reaches the user;
3. whether request accepted, approval recorded, provider accepted, domain effect established, partial effect and effect indeterminate remain impossible to confuse;
4. whether stale target/population/authority/evidence/recipient changes always invalidate preview and confirmation;
5. whether the four `BulkExecutionPolicy` modes close dependency, stop/continue, false atomicity, per-item identity and unknown-effect behavior;
6. whether tasks, queues, history, saved views and navigation can become a universal case root or manual domain-state writer;
7. whether approval/DOA/delegation/represented-principal interaction stays distinct from AwardDecision, Commitment and other effects;
8. whether the bounded hybrid external model is genuinely low-friction without mandatory account/network while remaining secure against forwarding, shared-mailbox ambiguity, contact transfer and cross-tenant leakage;
9. whether `ExternalSubmissionAcceptancePolicy` and the closed dispositions unambiguously decide evidence-only, provisional, valid, invalid, late, withdrawn, superseded and quarantined responses;
10. whether buyer-on-behalf capture preserves external source and internal actor without impersonation;
11. whether addendum/revision and structured offline files preserve exact version and cannot silently overwrite or enter the response population;
12. whether evidence/source/normalized/evaluation/issued/annotation/correction layers and communication occurrence/effect states remain distinct;
13. whether `SurfaceDisclosureProfile` and `DisclosureParityManifest` prevent subset, range, restricted, stale, indeterminate, blocked, issued/restated and reliance states from being laundered in compact, mobile, export, print, email or chat surfaces;
14. whether old reports require current reliance before new approval/award use;
15. whether control queues, accepted variance, errors, retry and offline/manual fallback avoid workflow/GRC/shadow-truth expansion;
16. whether accessibility, mobile support declaration, localization, Arabic/RTL, date/timezone/decimal/currency and translated-source boundaries are semantically sufficient while leaving physical choices open;
17. whether conventional A0–A3 work remains complete with no connector, persistent supplier account, chat, AI, warehouse or P07;
18. whether any rule creates a page/form/BPM/CDE/collaboration/GRC/BI/supplier-network/AI second XL.

Attack every hostile scenario in the packet and add your own.

Do not fail for frontend framework, component library, physical database/cache/search, exact schemas, renderer, pixels/branding, detailed WCAG testing technology, AI model/orchestration or product code intentionally deferred.

Return exactly the required structure:

- VERDICT
- BLOCKERS
- WATCHES / NON-BLOCKING DEBT
- GATE CHECK G1–G16
- REGRESSION CHECK
- ADR IMPACT
- P1.10 READINESS

Reconcile ADR-0016 and ADR-0038–ADR-0041. Confirm ADR-0017 remains P1.10-owned.

A clean PASS is appropriate only if no later frontend/physical/P1.10 work still has to decide operation authority, pre-result continuation/recovery, external submission validity, bulk effect semantics, limitation placement/parity, historical reliance or conventional-channel completeness.
