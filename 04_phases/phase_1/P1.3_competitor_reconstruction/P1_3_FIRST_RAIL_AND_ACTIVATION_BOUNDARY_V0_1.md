# P1.3 — First Rail & Activation Boundary v0.1

**Status:** PROVISIONAL BOUNDARY INPUT / FEEDS P1.4

## 1. First monetization rail

The first commercial surface remains:

`requirement / material request / package`
`→ RFQ/tender`
`→ supplier response capture`
`→ normalization / comparison`
`→ recommendation / approval`
`→ AwardDecision`
`→ external handoff`

This surface may start from either:
- lightweight material/request UX; or
- complex package/tender UX.

Both converge on the same sourcing/comparison/award substrate.

## 2. Kojo inheritance

Kojo contributes:
- low-friction field/material request UX;
- ordinary-material vocabulary;
- minimal user effort to create a request.

It does **not** contribute a second direct-order product surface to A0–A3.

Direct-source/direct-purchase remains a valid P1.2 domain route but is deferred from the first monetization rail.

## 3. Activation layers

### A0 — bootstrap
Minimum company/legal entity/project/user/role/money/time defaults.

### A1 — source
Simple or complex requirement intake, vendor minimum, RFQ/tender, evidence and external access.

### A2 — compare
Quote/revision truth, normalization, mappings, coverage/technical/commercial comparison, adjustments, snapshot.

### A3 — decide
Recommendation, justification, approval/DOA, award, external handoff.

### A4 — later commercial execution
Direct-source route where applicable, commitment formation, framework/call-off, change, receipt, valuation, recovery, accounting coexistence.

### A5 — optional overlays
Deep supplier lifecycle, live portfolio/long-lead views, named integrations, advanced AI, supplier network, broader analytics.

## 4. First-value invariants

A0–A3 must not require:
- internal P07 execution;
- ERP/CDE connector;
- persistent supplier account/network;
- CPM/BPM configuration;
- inventory/WMS;
- customer-designed ontology;
- direct-source product surface.

Award/handoff is a valid terminal point for the first rail.

## 5. Economic validation metric

A2 must be measured against current contractor comparison effort.

Required pilot measures:
- response receipt → comparison-ready elapsed time;
- buyer manual minutes per bid;
- clarification loops;
- mapping/coverage decisions;
- reusable schema/mapping leverage;
- current Excel/manual baseline.

Architecture PASS does not imply commercial PASS if normalization remains slower/more expensive than the incumbent workflow.
